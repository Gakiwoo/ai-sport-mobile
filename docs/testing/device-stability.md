# 低端 Android 30 分钟稳定性验收

> 自动化门禁已经提供，真实设备测试尚未执行。模板不能作为通过证据。

## 验收目标

- 使用计划投放的低端 Android 平板和正式候选安装包。
- 连续训练时间不少于 30 分钟。
- App 崩溃次数为 0。
- PerformanceMonitor 会话累计时间不少于 30 分钟。
- 按帧数加权的平均推理耗时不超过 150ms。
- 同时记录 p95 推理耗时、总帧数、设备温度和异常现象，p95 当前只报告不设硬门禁。

## 执行步骤

1. 从 `device-stability-template.json` 创建本次测试记录。
2. 填写设备厂商、型号、系统版本、App 版本和实际开始时间。
3. 依次完成跳绳、深蹲、仰卧起坐和开合跳训练，保持 App 连续运行。
4. 将 PerformanceMonitor 保存的真实会话报告填入 `sessions`。
5. 填写结束时间和崩溃次数，将 `status` 改为 `completed`。
6. 运行严格门禁：

```powershell
npm run test:device-stability -- <报告文件.json>
```

## 失败处理

任何以下情况均视为未通过：时长不足、报告字段缺失、崩溃次数不为 0、没有性能帧，或加权平均推理耗时超过 150ms。失败报告应保留，不要修改原始数据来满足门禁。
